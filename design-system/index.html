  • At most one primary action per screen. Primary never means new, recommended or important.
  • Status colours report state only. Never actions, emphasis or decoration.
  • Colour is never the only signal. Pair it with an icon or text.
  • No hex values in component or page CSS.
  • Only tokens switch with the mode. A fixed colour (hex, --bs-white, a palette step) stays the same in dark mode, so use it only where that is meant, such as text on a photo.

Decided: the focus ring is Bootstrap’s 3px ring in full-strength blue-500 (#0087fe) for every theme, about 3.6:1 on white. It passes the 3:1 the Colour guideline asks for focus indicators.

Decided: client zone is Bootstrap orange-600 (#cd5100), about 4.4:1 on white, so the icon passes the 3:1 WCAG 2.1 AA needs for icons. It replaces the mapping’s #EF7428 and orange-500 (about 2.9:1).

  • Heading roles use size utilities: .fs-2xl page title, .fs-lg section heading, .fs-md card or group heading. No custom heading scale.
  • The heading element follows the page structure, not the size. For example <h1 class="fs-2xl fw-semibold">.
  • Weights 400 and 600 only. Never 500: Segoe UI on Windows has no Medium face. Replace .fw-medium with .fw-semibold.
  • De-emphasise with colour (.fg-2, .fg-3), not size, weight or italics.
  • 12px is the floor. Never for anything people must read to finish a task.

Components

Every Bootstrap 6 component used in the Selection and Manage Audition prototypes. Codes match the Component mapping document. Form controls have their own Forms section, larger compositions have their own Organisms section, and the header, subheader band and footer are in App shell.

Forms

Form controls, laid out as in the Bootstrap 6 docs. Every input sits beside a label, and filters use the Combobox.

Organisms

Larger compositions built from components. Each one does a whole job on a page.

Organisms: Area specific

Organisms used in one area of the product only, such as the Sedcard. Shared organisms are in Organisms.

App shell

The elements that frame every page and never change: header, subheader band and footer. Pages and templates sit inside them.

Templates

Whole pages built from organisms, inside the App shell.

Component candidates

Custom components the product uses today that are not ready to build with. Each one waits for one of three decisions: keep it custom and document it, align it with Bootstrap 6 defaults, or review the UX of the page it lives on first. Do not use these in new work until they move out of this section.

Prototype kit

Start any prototype from the real design system. Claude Design, Claude Code, Lovable, v0 or Bolt: the prototype loads the same CSS as this library, and copies markup from it. Nothing gets rebuilt, so nothing drifts.

Step 1Copy the prompt

One block: the rules, the CSS links and the starter page with the header and subheader band.

Step 2Say what to build

Paste it into the tool and replace the last line with the screen you want.

Step 3Check the result

Paste the prototype's HTML into the checker at the bottom. It finds classes and combinations the design system does not allow.

The prompt

Works as one message in Claude Design, Claude Code, Lovable, v0 and Bolt. For a tool with a project knowledge or custom instructions setting, put the brief there once and send only what to build each time.
